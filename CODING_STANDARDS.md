# Стандарты кода (правила-суждения)

Читается при ревью. Всё, что проверяется машиной, живёт в конфигурации линтера, а не здесь.

## Тесты

- Тест проверяет внешнее поведение через HTTP API сервиса (см. ADR 0002), а не устройство внутренних пакетов.
- Провайдеры LLM в тестах подменяются фейковыми HTTP-серверами. Реальные модели в тестах не вызываются.
- Redis в тестах настоящий, не мок: поведение лимитов и кэша зависит от него.

## Дизайн

- Интерфейс провайдера остаётся маленьким. Новый провайдер подключается реализацией одного интерфейса без правок остального кода.
- Новый код следует соглашениям соседних файлов: имена, обработка ошибок, структура пакетов.
- Нет кода «на будущее»: каждая функция нужна текущему шагу спеки.
- Тестовая инфраструктура, которую требует issue (например, настоящий Redis в стенде), не считается кодом «на будущее».

## Ядро и объяснимость

- Изменение ядра (гейтвей, цикл агента, оркестратор) сопровождается пояснением и 3–5 вопросами для самопроверки в описании PR. Без них PR не готов к мерджу.
- Один PR соответствует одному небольшому куску спеки.
