# 0004. Раскладка пакетов гейтвея и правила зависимостей

Дата: 2026-10-24. Статус: принято.

## Решение

Код гейтвея лежит в `app/internal/`, один пакет на одну ответственность:

- `httpapi`: HTTP-слой (обработчики, разбор запроса, формат ошибок) и сборка гейтвея из конфигурации (`New`);
- `auth`, `ratelimit`, `cache`, `routing`: правила, которые не знают про HTTP;
- `provider` (интерфейс и общие типы), `provider/openai`, `provider/claude`: вызовы провайдеров;
- `chatwire`: помощники формата OpenAI chat completions;
- `config`: разбор конфигурации.

Правила зависимостей:

1. `httpapi` знает про все остальные пакеты, они про него не знают.
2. `auth`, `ratelimit`, `cache`, `routing` не импортируют друг друга. Их склеивает `httpapi`.
3. Реализации провайдеров импортируют только `provider` и `chatwire`. Остальной код видит их через интерфейс `provider.Provider`.
4. Новые правила (бюджет, учёт стоимости, fallback, circuit breaker) кладутся в свои пакеты по тем же правилам, а не в `httpapi`.
5. Новый тип провайдера добавляется пакетом в `provider/` и строкой в `httpapi.newProvider`.

## Почему

Всё лежало в одном пакете `server`: обработчик, кэш, лимитер и перехват потока. С каждым тикетом он рос бы дальше. Раздельные пакеты не дают одному правилу тянуть за собой другие и позволяют читать каждое правило отдельно.

## Последствия

Шов тестов не меняется (ADR 0002): тесты остаются в `httpapi` и идут через HTTP API. Пакеты правил не имеют собственных тестов, их поведение проверяется через сервис.
