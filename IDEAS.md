## Q6. Варианты домена

### A. RAG и знания
1. **Мультитенантный RAG-сервис.** Загрузка документов, фоновая индексация через очередь, гибридный поиск (BM25 + векторы), квоты на тенанта, eval качества поиска.
2. **Поиск по кодовой базе.** Индексация git-репозитория через AST-чанкинг (`go/ast`), вопросы вроде «где обрабатывается оплата?» с ссылками на файлы и строки.
3. **Помощник по внутренней документации.** Интеграция с Notion или Confluence, актуальный индекс, ответы с источниками.

### B. Агенты
4. **Агент для разбора инцидентов.** Получает алерт, сам вызывает tools (логи, метрики, последние деплои), строит гипотезу и пишет разбор.
5. **Агент-ревьюер Pull Request'ов.** Webhook от GitHub, анализ диффа, комментарии на строках.
6. **Text-to-SQL агент.** Вопрос на естественном языке превращается в безопасный SQL: read-only доступ, валидация, объяснение.
7. **Оркестратор мультиагентной системы.** Планировщик раздаёт подзадачи воркерам на горутинах.

### C. Инфраструктура вокруг LLM
8. **LLM-гейтвей.** Единая точка входа: кэш (в том числе семантический), rate limit, fallback между провайдерами, учёт токенов и стоимости, трейсинг.
9. **Платформа для eval и регрессии промптов.** Прогон датасета через разные версии промпта и модели, сравнение метрик, отчёты.
10. **Очередь пакетной LLM-обработки.** Классификация и извлечение данных на больших объёмах: ретраи, идемпотентность, контроль бюджета.

### D. Прикладные продукты
11. **Умный разбор резюме и вакансий.** Извлечение структуры, матчинг, ранжирование.
12. **Голосовой ассистент.** Telegram-бот, транскрибация, LLM, ответ голосом.
13. **MCP-сервер** для собственных данных или сервиса, подключаемый к Claude.

## Выбранный проект: Incident Copilot (1 + 4 + 7 + 8)

Поток: приходит алерт → оркестратор (7) раздаёт подзадачи воркерам-агентам (4) → один из воркеров ищет похожие инциденты и ранбуки через RAG (1) → все вызовы LLM идут через собственный гейтвей (8) с кэшем, лимитами и учётом стоимости.

Запасной вариант, если что-то пойдёт не так: 1 + 9 (RAG-сервис с платформой eval).

## Процесс работы с агентом

| # | Решение |
|---|---------|
| Q19 | Перед мерджем каждого PR по ядру я должен объяснить своими словами, что делает код, почему так и что сломается без ключевой части. Агент кладёт в PR пояснение и 3–5 вопросов для самопроверки. Для рутины (Dockerfile, CI) вопросы не нужны |
| Q20 | Цикл: спека → агент в ветке пишет код и гоняет тесты → PR → моё ревью → комментарии → правки агента → мердж → следующий кусок. Ralph loop работает внутри куска (лимиты на итерации и бюджет), ревью стоит между кусками как обязательные ворота. Один PR — один небольшой кусок, до 300–400 строк |
| Q21 | Спеки пишу я (с помощью интервью): интерфейс, поведение, критерии приёмки. Тесты утверждаю до реализации (TDD, скилл `mattpocock-skills:tdd`) |
| Q22 | Первый проход ревью: скилл `mattpocock-skills:code-review` (Standards + Spec). Финальный судья — я |

В README будет отдельный раздел «как я строил проект с агентами и как контролировал качество».

## Локальные модели

Железо: Mac 16 ГБ, `llama-swap` на `localhost:7382` (конфиг `~/models/llama-swap.yaml`). Профили: `research` (Qwen3.5-4B Q8, контекст 32k), `agent` (Qwen3.5-4B Q8, 16k), `coder` (omnicoder-9B Q4, 16k). Модели медленные и с маленьким контекстом.

| # | Решение |
|---|---------|
| Q23 | В разработке локальные модели делают только мелкую механику в пределах 16k: моки, table-driven тесты по готовому интерфейсу, докстринги, форматирование, переименования. Результат всё равно ревьюится. В Ralph loop не участвуют. Если не справились за 2–3 попытки, задачу берёт Claude |
| Q24 | В продукте: маршрутизация в гейтвее. Простые задачи (классификация алерта, краткое резюме логов) идут на локальную модель, сложные рассуждения на Claude. Grafana показывает экономию. Лимит контекста 16k используем как реальное условие: воркер логов режет вывод Loki под окно |
| Q25 | Eval из Q15 гоняем в двух режимах: «только Claude» и «с роутингом на локальную модель». Сравнение качества и стоимости в README таблицей |
| Q26 | Модели запускаются по очереди (llama-swap). В docker-compose задаём лимиты памяти, eval на локальной модели запускается отдельной командой |
